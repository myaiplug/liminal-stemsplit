Audio ffmpeg

The single most important tool in any creator's pipeline. ffmpeg converts, trims, merges, compresses, and inspects every audio and video format that exists.

Quick Start

Terminal

After installing, verify: ffmpeg -version

Everyday Workflows

  • Convert MP3 to WAV: ffmpeg -i input.mp3 output.wav
  • Trim from 0:30 to 1:00: ffmpeg -i input.mp3 -ss 30 -to 60 -c copy output.mp3
  • Merge two audio files: ffmpeg -i "concat:file1.wav|file2.wav" -acodec copy merged.wav
  • Extract audio from video: ffmpeg -i video.mp4 -vn -acodec libmp3lame audio.mp3
  • Change sample rate to 44100: ffmpeg -i input.wav -ar 44100 output.wav
  • Batch convert all MP3s to WAV in a folder: for %f in (*.mp3) do ffmpeg -i "%f" "%~nf.wav"
  • Inspect file metadata: ffprobe input.wav

Troubleshooting

SYMPTOM

"ffmpeg is not recognized" — Reopen your terminal after install, or add D:\AI-Tools\ffmpeg\bin to your PATH manually.

SYMPTOM

Audio is sped up or slowed down after conversion — You're likely mixing sample rates. Use -ar 44100 explicitly to force a consistent rate.

Pro Tips

  • ffmpeg reads stdin from a pipe. You can chain it with any tool: sox input.wav -t wav - | ffmpeg -i - output.mp3
  • Use -af "loudnorm" to normalize volume to broadcast standard in one pass.
  • ffmpeg's -threads auto flag maximizes multi-core CPU usage for encoding.

💡 Hardware tip: ffmpeg benefits from a fast CPU for encoding. An Intel i7-13700K encodes 4x faster than a laptop i5.

Audio SoX — Swiss Army Knife of Audio

SoX does one thing ffmpeg can't: surgical audio manipulation. Trim silence, apply effects, change tempo without pitch shift, generate tones.

Quick Start

Terminal

sox --info input.wav — prints sample rate, channels, duration, bit depth.

Everyday Workflows

  • Trim silence from start/end: sox input.wav output.wav silence 1 0.1 1% -1 0.1 1%
  • Change tempo without pitch shift: sox input.wav output.wav tempo 1.25 (25% faster)
  • Pitch shift up 3 semitones: sox input.wav output.wav pitch 300 (300 cents = 3 semitones)
  • Apply reverb: sox input.wav output.wav reverb 50 50 100 (room, wetness, delay)
  • Concatenate multiple files: sox file1.wav file2.wav file3.wav merged.wav
  • Generate a 440Hz sine tone (5 seconds): sox -n output.wav synth 5 sine 440
  • Reverse audio: sox input.wav output.wav reverse

Troubleshooting

SYMPTOM

"sox FAIL sox: Input files must have the same sample rate" — Use sox --combine concatenate -r 44100 file1.wav file2.wav output.wav

Pro Tips

  • SoX's stat effect prints detailed RMS, peak, and DC offset: sox input.wav -n stat
  • Chain effects: sox input.wav output.wav tempo 1.1 reverb 30 pitch 200 — order matters!
  • The compand effect is a simple compressor: sox input.wav output.wav compand 0.3,1 6:-70,-60,-20 -5 -90 0.2

Audio Pedalboard — Python Audio Effects

Spotify's open-source audio effects library. Think of it as "pedalboard effects in Python" — reverb, delay, compression, distortion, noise gate, pitch shift, all real-time or offline.

Quick Start

Python
from pedalboard import Pedalboard, Reverb, Delay, Compressor
from pedalboard.io import AudioFile

with AudioFile("input.wav") as f:
  audio = f.read(f.frames)
  sr = f.samplerate

board = Pedalboard([Reverb(room_size=0.5), Delay(delay_seconds=0.25)])
effected = board(audio, sr)

with AudioFile("output.wav", "w", sr, effected.shape[0]) as f:
  f.write(effected)

Everyday Workflows

  • Mastering chain: Compressor → Limiter → Low-pass filter: Pedalboard([Compressor(threshold_db=-20), Limiter(), LowpassFilter(cutoff_frequency_hz=18000)])
  • Lo-fi effect: Bitcrush + low-pass: Pedalboard([Bitcrush(bit_depth=8), LowpassFilter(cutoff_frequency_hz=8000)])
  • Noise gate: Pedalboard([NoiseGate(threshold_db=-40, ratio=10)])
  • Pitch shift + formant preserve: Pedalboard([PitchShift(semitones=2)]) — uses rubberband internally

Troubleshooting

SYMPTOM

"ModuleNotFoundError: No module named 'pedalboard'" — Run pip install pedalboard from an admin terminal.

SYMPTOM

Audio crackles after processing — Your buffer size is too small. Add buffer_size=512 to the Pedalboard constructor.

Pro Tips

  • Pedalboard supports VST3 plugins. Load any VST3 you own: Pedalboard([load_vst3_plugin("C:\\VSTPlugins\\MyPlugin.vst3")])
  • Process audio in real-time through a microphone with pedalboard_sink = AudioStream()
  • Batch process a folder of WAVs: loop over files, apply the same board, save to /processed/.

Image ComfyUI — Image Generation Workstation

Node-based interface for Stable Diffusion, FLUX, and every image model. Think of it as "visual programming for AI images." More powerful than Auto1111, steeper learning curve, worth every minute.

Quick Start

Launch

Run: D:\ComfyUI\run_nvidia_gpu.bat

Wait for "To see the GUI go to: http://127.0.0.1:8188"

Open browser to http://127.0.0.1:8188

Your First Image (30 seconds)

ComfyUI

1. You'll see a default "text-to-image" workflow already loaded (if not, click "Load Default")

2. In the CLIP Text Encode (Positive) node, type: cinematic photo of a foggy cyberpunk street, neon signs, volumetric lighting, 8k

3. Click Queue Prompt (or Ctrl+Enter)

4. Your image appears in ~8-12 seconds

Everyday Workflows

  • Text-to-image (SDXL): Use the default workflow but switch the checkpoint to juggernautXL_v10.safetensors in the Load Checkpoint node
  • Image-to-image: Add a Load Image node → connect to a second CLIP Text Encode → feed into KSampler's latent
  • Inpaint (fix specific areas): Load image + mask → VAE Encode (for inpaint) → KSampler → VAE Decode
  • Upscale 2x: After generation, route image through a UpreScale node (using Real-ESRGAN or nearest-exact)
  • Batch generation: Change the KSampler's batch_size from 1 to 4 to generate 4 images at once

Troubleshooting

GUI not loading

If browser shows blank page, check terminal for port conflicts. Kill with Ctrl+C and restart on a different port: python main.py --port 8189

Out of memory (CUDA OOM)

Drop image size from 1024x1024 to 768x768, or switch from SDXL to SD 1.5 checkpoint. In ComfyUI-Manager, enable "Low VRAM Mode".

Black images

Usually means a VAE mismatch. Add a separate "Load VAE" node and explicitly set it to the same model's vae. common with SDXL fine-tunes.

Pro Tips

  • Install ComfyUI-Manager (already done if you ran the installer). It gives you a one-click "Install Missing Custom Nodes" button that saves hours of debugging workflows from Civitai.
  • Use Ctrl+Drag to grab the entire node graph and move it. Use Ctrl+M to mute a node (keeps it in place but disables it).
  • Save your workflows! Click the gear icon → "Save (API Format)" — this creates a shareable JSON that recreates your entire node setup.
  • The KSampler node's seed parameter locks the noise pattern. Change it by 1 for a completely different image with the same prompt.

🖥️ SDXL runs best on 10GB+ VRAM. If your 8GB card struggles, a used RTX 3080 (10-12GB) is the best upgrade for AI image gen under $500.

Image SDXL & FLUX — Which Model When

SDXL (Juggernaut XL, RealVisXL)

  • Best for: Photorealism, portraits, landscapes, product shots
  • VRAM: 7-8GB (tight on 8GB, use --medvram)
  • Resolution: 1024x1024 native (don't go lower, don't go much higher without upscaling)
  • Speed on 2080 SUPER: ~8-10 seconds per image
  • Download: https://civitai.com/models/133005/juggernaut-xl

FLUX.1-dev

  • Best for: Prompt adherence, complex scenes, text in images (signs, posters)
  • VRAM: 6-8GB in 4-bit (12GB+ in FP16 — skip FP16 on 8GB cards)
  • Resolution: 1024x1024 native (same as SDXL)
  • Speed on 2080 SUPER: ~25-35 seconds per image (slower but better quality)
  • Pro tip: Use FLUX for "illustration" styles and SDXL for "photorealistic". They complement each other.
FLUX needs special nodes

Install via ComfyUI-Manager: search for "FLUX" and install the FLUX workflow. The default KSampler won't work — FLUX uses a different pipeline.

Video AnimateDiff — Image to Animation

Turns any Stable Diffusion image into a short animated clip. Motion modules control the type of movement: camera pan, walk cycle, flowing hair, pulsing lights.

Quick Start

ComfyUI

AnimateDiff runs as a node within ComfyUI. After installing the custom node, you'll see "AnimateDiff Loader" and "AnimateDiff Sampling" in the node menu.

Your First Animation

AnimateDiff

1. Load your checkpoint (SD 1.5 recommended for first try — it's faster)

2. Add an AnimateDiff Loader node → select a motion module (mm_sd_v15_v2)

3. Add an AnimateDiff Sampling node between your KSampler and VAE Decode

4. Set KSampler's batch_size to 16 (that's 16 frames)

5. Queue Prompt — wait ~2 minutes for 16 frames at 512x512

Motion Module Guide

  • mm_sd_v15_v2: General-purpose. Smooth, predictable motion. Start here.
  • mm_sdxl_v10_beta: SDXL version. Higher quality but needs 10GB+ VRAM. Test with short 8-frame sequences.
  • Temporal LoRA: Adds specific motion types (camera zoom, walk cycle, liquid flow). Load as a separate LoRA node.

Troubleshooting

Extremely slow (5+ min per animation)

Drop resolution to 512x512, reduce batch_size to 8, use SD 1.5 not SDXL. With 8GB VRAM, 16 frames at 512x512 takes ~90 seconds.

Frames are identical (no motion)

Make sure the AnimateDiff Sampling node is connected between the KSampler and VAE Decode. If it's after the decode, no motion is applied.

Pro Tips

  • Generate a static image first, note the seed, then plug that same seed into AnimateDiff for consistent starting frames.
  • Use VideoHelperSuite to add frame interpolation between the 16 generated frames → output 32-frame smooth video at 12fps.
  • Output as GIF for web sharing or MP4 (via ffmpeg) for production.

LLM Ollama — Local LLM Engine

One command to download and run any open-source LLM. Ollama manages model downloads, GPU acceleration, and exposes a local API that every tool in the ecosystem talks to.

Quick Start

Terminal

ollama run llama3.1:8b

Wait for the download (~4.7GB) and you're in a ChatGPT-like chat immediately. Type your first question.

Everyday Workflows

  • Chat: ollama run llama3.1:8b → type naturally, /exit to quit
  • One-shot prompt (no chat): ollama run llama3.1:8b "Write a Python function to reverse a linked list"
  • Use a different model: ollama run qwen2.5-coder:7b (coding), ollama run mistral:7b (general, less censored)
  • List downloaded models: ollama list
  • Remove a model: ollama rm llama3.1:8b
  • REST API (used by OpenCode, Continue.dev, Open WebUI): curl http://localhost:11434/api/generate -d '{"model":"llama3.1:8b","prompt":"Hello"}'

Model Comparison (Run Each and Compare)

  • llama3.1:8b — Best all-around. Polite, helpful, follows instructions well. Heavily censored.
  • qwen2.5-coder:7b — Best for code. Understands context better than CodeLlama. Use as your primary coding assistant.
  • mistral:7b — Fastest inference. Less censored. Feels more "natural" in conversation. Good for roleplay or creative writing.
  • deepseek-coder-v2:16b-lite — Borderline on 8GB but has 128K context window. Can analyze entire codebases. If VRAM is tight, close other apps.

Troubleshooting

"Error: model requires more VRAM"

Ollama auto-detects VRAM. If you hit the ceiling, run a smaller quantized version: ollama run llama3.1:8b-q4_K_M (uses ~4GB instead of ~5.5GB).

Slow responses

Check if Ollama is using your GPU: ollama run llama3.1:8b while running nvitop in another terminal. If GPU utilization is 0%, set OLLAMA_GPU_OVERHEAD=0.1 environment variable.

Pro Tips

  • Set a custom system prompt: ollama run llama3.1:8b --system "You are a sarcastic British butler. Answer every question with dry wit."
  • Use continue.dev (VS Code extension) with Ollama for inline code completion — it's like Copilot but free.
  • Run Open WebUI in Docker: docker run -d -p 3000:8080 ghcr.io/open-webui/open-webui:main — gives you a ChatGPT-like web UI that talks to your local Ollama.
  • Ollama's models download once and cache forever. No ongoing data costs.

💻 For coding, pair Ollama with a 1440p ultrawide monitor. Having your code + AI assistant side by side doubles productivity.

Audio Demucs v4 — Stem Splitter

The industry standard for separating a mixed song into individual stems: vocals, drums, bass, and other instruments. Used by mastering engineers, remixers, and sample producers worldwide. Completely free, open source, runs on your GPU.

Quick Start

Terminal

demucs "D:\My Music\song.mp3"

Wait ~15 seconds for a 3-minute song. Stems appear in ./separated/htdemucs/song/

Output Structure

Files created
separated/htdemucs/song/
├── vocals.wav      ← lead + backing vocals
├── drums.wav       ← kick, snare, hats, cymbals, toms
├── bass.wav        ← bass guitar, synth bass, sub bass
└── other.wav       ← guitars, keys, pads, FX, everything else

Everyday Workflows

  • Extract vocals for a remix: demucs song.mp3 → open vocals.wav in your DAW over a new instrumental
  • Make a karaoke track: demucs song.mp3 → mix drums.wav + bass.wav + other.wav together, leave out vocals.wav
  • Extract drum loop for sampling: Use demucs --two-stems=drums song.mp3 (faster: only extracts drums + no-drums)
  • Better vocal quality: After Demucs, run the vocals.wav through MelBand Roformer (the vocal-specific model)
  • Batch split a folder: for %f in ("D:\Songs\*.mp3") do demucs "%f"

Model Variants

  • htdemucs (default) — 4 stems. Best quality. Uses transformer + U-Net hybrid.
  • htdemucs_ft — Fine-tuned version. Slightly better separation but slower.
  • --two-stems=vocals — Splits into just "vocals" and "no_vocals". Fastest option.
  • --shifts=2 — Applies time shifting ensemble. Better quality, 2x slower. Use for important tracks.

Troubleshooting

Not separated well / bleed between stems

Try demucs --shifts=2 --overlap=0.25 song.mp3. The --shifts flag averages multiple passes and significantly reduces bleeding.

Out of memory on long tracks

Demucs processes in chunks. If a 10-minute track OOMs, split it with ffmpeg first: ffmpeg -i song.mp3 -ss 0 -t 300 part1.wav

CPU only (very slow)

Demucs auto-detects CUDA. Verify: python -c "import torch; print(torch.cuda.is_available())". If False, reinstall PyTorch with CUDA: pip install torch --force-reinstall --index-url https://download.pytorch.org/whl/cu118

Pro Tips

  • Demucs outputs 44.1kHz 24-bit WAV files. Import directly into any DAW — they'll be sample-aligned with the original.
  • Phase issues? Sum the stems back together in your DAW. If they don't null out against the original, add a utility plugin with polarity flip on the "other" stem.
  • For the absolute highest quality vocal extraction, run Demucs → feed vocals.wav into MelBand Roformer → get cleaner-than-cloud results.

🎛️ Good headphones reveal separation artifacts that cheap earbuds mask. If you're splitting stems for production, invest in closed-back monitoring headphones.

Audio Whisper large-v3 — Audio Transcription

OpenAI's speech-to-text model, run entirely locally. Transcribes anything: interviews, podcasts, lectures, meetings, vocal takes. Supports 99+ languages.

Quick Start

Terminal

whisper "interview.wav" --model large-v3

Outputs: .txt, .srt (subtitles), .vtt, .tsv, .json — all in the same folder as the audio.

Everyday Workflows

  • Transcribe a podcast: whisper podcast.mp3 --model large-v3 --language en
  • Generate subtitles for video: whisper video.mp4 --model large-v3 --output_format srt → import .srt into any video editor
  • Transcribe with timestamps for editing: whisper raw_vocals.wav --model large-v3 --output_format json → each word has start/end times
  • Translate to English (for non-English audio): whisper podcast.mp3 --model large-v3 --task translate
  • Faster transcription (lower accuracy): whisper podcast.mp3 --model small (uses 1GB VRAM instead of 4GB, 5x faster)

Model Size Guide

  • tiny (~1GB VRAM): Fast but misses quiet dialogue. Good for checking timestamps.
  • small (~2GB VRAM): Good balance. Works on any GPU.
  • medium (~3GB VRAM): Better accuracy. Recommended for clean audio.
  • large-v3 (~4GB VRAM): Best accuracy. Handles accents, background noise, multiple speakers. This is the one you want for production.

Troubleshooting

"RuntimeError: CUDA out of memory"

Use --device cpu to run on CPU (slower but works). Or switch to --model small.

Transcription has repeated phrases

This is a known issue with large-v3 on long audio. Split the audio into 10-minute chunks: ffmpeg -i long.wav -f segment -segment_time 600 chunk_%03d.wav

Pro Tips

  • For podcasts with multiple speakers, run the audio through a voice-activity detector first (Python's webrtcvad) then transcribe each segment. Whisper will produce separate captions per speaker.
  • Whisper's JSON output includes per-word confidence scores. Filter out words below 0.5 confidence for cleaner transcripts.
  • Combine Whisper + Demucs: separate vocals from music first, then transcribe just the vocals for cleaner podcast transcription.

Audio XTTSv2 — Voice Cloning

Clone any voice from a 6-second audio sample. Multilingual. Generates natural speech with the tone, cadence, and emotion of the original speaker.

Quick Start

Terminal

tts-server --model_name tts_models/multilingual/multi-dataset/xtts_v2

Opens a web UI at http://127.0.0.1:8020

Your First Voice Clone

Web UI

1. Upload a 6-30 second WAV of the voice you want to clone (clean recording, no background music)

2. Type text to generate

3. Select language (English, Spanish, French, German, etc.)

4. Click Generate → your cloned voice speaks your text

Everyday Workflows

  • Narrate a video: Clone your own voice, generate a script, stitch audio to video timeline
  • Character voices for games: Clone a distinctive voice, then generate dialogue lines
  • Multilingual content: Clone voice in English, generate text in French/Spanish — the voice's timbre carries over
  • Audiobook production: Generate long-form narration with consistent voice throughout

Troubleshooting

Voice sounds robotic or flat

Your sample needs more variation in pitch and tone. Use a recording where the person speaks naturally for at least 10-15 seconds with varying intonation.

"CUDA out of memory"

XTTSv2 needs ~3GB VRAM. Close ComfyUI or Ollama while running it. Or add --cpu flag for slower CPU inference.

Pro Tips

  • For the best clones, record your sample in the same acoustic environment you'll use for final generation.
  • Add "SSML" tags to control emphasis: <emphasis level="strong">This word is important</emphasis>
  • Combine XTTSv2 + AceStep: generate a beat, then generate vocals with a cloned voice over the top.

Audio RVC WebUI — Voice Conversion (Singing)

Unlike XTTSv2 (which generates speech), RVC converts existing audio into another voice. Famous for "singing voice conversion" — take a vocal performance and make it sound like a different singer.

Quick Start

Launch

Run: D:\RVC-WebUI\go-webui.bat

Open: http://127.0.0.1:7865

Your First Voice Conversion

RVC

1. Upload a vocal WAV file (clean vocals, no instrumental)

2. Select a pretrained model from the dropdown (or Train your own with 10+ minutes of a single speaker)

3. Click "Convert"

4. Your vocals are now "sung by" the target voice. Download the result.

Everyday Workflows

  • Sing your lyrics in another voice: Record yourself singing → convert to any trained model
  • Create harmonies: Convert the same vocal take with different voice models → mix together in your DAW
  • Restore a damaged vocal take: If one section of a recording is ruined, re-sing that section and convert it to match the original singer

Training Your Own Model

  • Collect 10-30 minutes of clean audio from one speaker (no background music, one voice only)
  • In the RVC WebUI, go to "Train" tab
  • Upload your dataset (ZIP of WAVs or a folder path)
  • Set model name → click "Train" → wait 1-3 hours depending on dataset size

Pro Tips

  • RVC sounds best when the source and target voices have similar pitch ranges. Converting a baritone to a soprano produces artifacts.
  • Clean up the input vocals with Demucs + MelBand Roformer before feeding into RVC — cleaner input = cleaner conversion.
  • For real-time voice conversion (live streaming), use the RVC "Real-time" tab with loopback audio device.

Image Real-ESRGAN — Image Upscaling

Upscale images 4x with AI. No quality loss. Works on photos, AI art, screenshots, old family photos. The difference between "pixelated mess" and "usable in 4K."

Quick Start

Terminal

realesrgan -i input.jpg -o output_4x.png -s 4 -n RealESRGAN_x4plus

Turns a 512x512 image into 2048x2048 with sharp, natural-looking detail.

Everyday Workflows

  • Upscale AI art from SDXL: realesrgan -i comfyui_output.png -o upscaled.png -s 4 (512→2048 or 1024→4096)
  • Restore old photos: Run through GFPGAN first (face restore), then Real-ESRGAN (upscale)
  • Anime/manga upscaling: realesrgan -i manga.jpg -o hq.png -s 4 -n RealESRGAN_x4plus_anime_6B (special anime model)
  • Batch upscale a folder: for %f in ("*.jpg") do realesrgan -i "%f" -o "upscaled\%~nf.png" -s 4

Model Guide

  • RealESRGAN_x4plus: General purpose. Best for photos, AI art, real-world images.
  • RealESRGAN_x4plus_anime_6B: Cartoon/anime. Trained on anime frames. Avoid for photos.

Pro Tips

  • Real-ESRGAN works best when input images are at least 256px on the shortest side. Upscaling 64x64 to 256x256 works but won't add detail that wasn't there.
  • For maximum quality, upscale in ComfyUI as part of your image generation workflow (latent upscale → Real-ESRGAN pass) rather than as a separate step.
  • Output as PNG (lossless) for archival, JPEG for web sharing.

🖨️ Printing your AI art? A 4x upscale from SDXL (1024→4096 pixels) is enough for a 13"x13" print at 300 DPI. Print on demand with quality paper matters more than resolution.

Image GFPGAN — Face Restoration

Fix faces in AI-generated images. Corrects deformed eyes, crooked noses, melted mouths — the "uncanny valley" artifacts that Stable Diffusion produces on faces.

Quick Start

ComfyUI

In ComfyUI, add a "Face Restoration (GFPGAN)" node between your VAE Decode and Save Image nodes. That's it — every generated face gets corrected automatically.

Everyday Workflows

  • Fix faces in AI portraits: Add GFPGAN node with strength=0.8 (lower = more subtle fix)
  • Restore old photos: python inference_gfpgan.py -i old_photo.jpg -o restored.jpg -v 1.4
  • Batch fix a folder of AI faces: Point ComfyUI batch mode at a folder, add GFPGAN node, queue.

Pro Tips

  • GFPGAN strength: 1.0 for badly deformed faces, 0.5 for minor tweaks, 0.3 for just sharpening existing good faces.
  • Some faces get "over-corrected" to look the same (GFPGAN has a "default face" bias). If every face starts looking like the same person, lower the strength to 0.4.
  • CodeFormer is an alternative to GFPGAN with different strengths. ComfyUI has both nodes — try both and pick per image.

System GPU Monitoring — nvitop & gpustat

Real-time GPU info: VRAM usage, temperature, power draw, processes using the GPU. nvitop is the prettiest terminal UI. gpustat is the quick one-liner.

Quick Start

Terminal

nvitop --colorful → full-screen real-time monitor (press q to quit)

gpustat → single-line summary that fits in a 80-char terminal

gpu → alias for nvitop --colorful

What to Watch

  • Used VRAM: If it's above 7.5GB on your 8GB card, you're about to OOM. Close something.
  • GPU-Util: 0% means the tool isn't using your GPU. Something's wrong with CUDA.
  • Temp: Above 85°C sustained = thermal throttling. Clean your fans or underclock.
  • Process list: Shows exactly which program is using your VRAM. Good for catching memory leaks.

When to Use Each

  • nvitop — When you're actively troubleshooting (OOM, slow inference, thermal issues). Leave it running in a second terminal.
  • gpustat — When you just want a quick check before launching a model. Type it, see if you have 2GB free, go.
  • nvidia-smi — Built-in but ugly. Only use when nvitop/gpustat aren't available (ssh without Python).

Pro Tips

  • Keep nvitop running in a second monitor while you work. Open it in a small terminal window pinned to the corner. Watch VRAM spike when you hit "Generate."
  • Some tools don't release VRAM immediately after finishing. If nvitop shows 6GB used but nothing is running, wait 30 seconds or restart the Python process.
  • gpustat's --watch flag refreshes every second: gpustat --watch — useful for monitoring during batch generation.
